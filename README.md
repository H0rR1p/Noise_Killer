# NoiseKiller

依据当前 v0.5 需求与架构构建的 Windows 用户态工程版本。当前路线已改为 **物理麦克风 → MECAG → WASAPI 播放 → 已安装第三方虚拟线路 → 游戏/通信应用**。不自建内核驱动，不需要为本项目安装 WDK、创建驱动测试 VM 或取得自有驱动签名；用户仍须另行安装、配置第三方线路。算法重叠目标保留及实际线路消费者验收仍未通过，不能称已完成 G3。

2026-10-13 工程状态：原 58 项冻结合成回归全部通过；新增独立生成信号开发回归为 43/47，仍有 4 项旁人/缺席抑制失败，探索检查 7/9。51 项核心契约、其他控制/输出检查及无采集冒烟通过，CTest 总体 **5/6，未全通过**。强干扰例目标保留从 71.65% 降至 70.38%，同 F0 旁人抑制仅 −5.34 dB，未达 −20 dB；不能称全面改善。当前源码是未验收研发原型，不发布通过版 ZIP。

当前 FeatureSchema 仍为 **3**，已有有效 schema 3 档案无需因本轮重录；旧版 1/2 必须显式重新注册，不自动改写、降级或静默迁移。算法版本 `0.2.4-mecag-g1-partial-harmonic-hypotheses`，应用工程版本 `0.2.2`，二者分别记录。

## 线路接入

以 [VB-CABLE 官方软件](https://vb-audio.com/Cable/)为例：

1. 用户自行从官方源安装虚拟线路，按厂商说明使用管理员权限并重启；本程序不下载、打包或静默安装驱动。
2. 在 NoiseKiller 选择物理输入麦克风，注册本人参考语音，再选择线路的**播放端点 `CABLE Input`**作为输出。
3. 在游戏/通信软件的麦克风设置中选择线路的**录音端点 `CABLE Output`**。这里 Input/Output 的名字描述线路方向，不是应用中的采集/播放方向。
4. 点击开启。没有选择正确线路、设备拔出或处理失败时拒绝启动/停止并清理自身缓存，不自动改用扬声器、物理原音或系统默认设备。

不要把游戏播放声音也路由到同一线路，不开启“侦听此设备”绕回线路；其他软件向同一线路播放的音频可能混入上行，NoiseKiller 不拥有第三方端点的独占权限。停止只能清理本应用的流和缓存，第三方驱动及目标应用的尾部残留仍需实测。当前普通 `CABLE Input`/`CABLE Output` 路由不包括 `CABLE In 16ch`。

## 构建和测试

Windows 10/11 x64、PowerShell 7、Visual Studio 2022 的 C++ 桌面工具及 Windows SDK。脚本只构建工作区代码，不安装系统组件、不修改安全启动或系统默认麦克风。构建脚本对子进程环境做大小写去重，避免宿主同时提供 `Path`/`PATH` 造成 MSBuild 失败；不修改系统环境。

```powershell
.\scripts\build.ps1
.\build\Release\noisekiller_holdout_tests.exe --protocol-only
```

默认构建脚本先编译，再执行全部测试；当前因四项已知留出抑制失败而返回失败。只编译调试程序可运行 `.\scripts\build.ps1 -SkipTests`，这不代表测试/验收通过；打包脚本仍必须运行完整测试，不能跳过门禁。

产物位于 `build/Release/NoiseKiller.exe`、`NoiseKiller.Cli.exe`。GUI 启动不会自动采集声音；本人注册由用户显式触发。未选择已安装的线路播放端点时不能启用在线过滤。设备捕获、注册录音、应用兼容和第三方软件安装由用户选择并在实际环境中验证。受限隔离账户下 DPAPI 可能没有可用的用户密钥环境；应在正常当前用户环境验证，程序不会降级到明文保存。

`scripts/package.ps1` 在测试通过后生成不覆盖旧文件的用户态工程 ZIP，**不是完整 MVP 安装包**；不含驱动/服务，不安装任何组件，也不打包合成测试档案或音频。

CLI 用于算法原型与本地文件验证，不表示实际第三方线路和游戏麦克风已验收：

```powershell
.\build\Release\NoiseKiller.Cli.exe enroll reference.wav profile.nkp
.\build\Release\NoiseKiller.Cli.exe process profile.nkp mixture.wav filtered.wav diagnostics.json
.\build\Release\NoiseKiller.Cli.exe benchmark profile.nkp 30
.\build\Release\NoiseKiller.Cli.exe devices
```

参考音为本人单独讲话的 10–30 秒录音。Profile 使用当前 Windows 用户 DPAPI 加密，不能回退明文或跨用户解密。CLI 不覆盖已有输出。实时 PCM 默认不落盘；CLI 仅在用户指定文件模式下产生 WAV，诊断不存完整谱或本人统计。

`devices` 只枚举活动 capture/render 端点，不启动音频流、录音或播放。

## 实现边界

- `SourceGrouper`、`IdentityMatcher`、`SourceTracker` 各自输出分组、参考身份和跨帧关联证据；联合竞争消费这些不同约束，不把它们并成四个声纹分。
- 16 kHz 单声道、160 样本 hop、480 样本历史窗、512 点 FFT；固定轨迹/别名/beam/谱基/迭代上限。功率贡献为统计近似，保留未知贡献，输出软掩码与有状态 OLA。
- 统计身份方法独立实现，没有捆绑未授权 ALIZE UBM 或大模型。宽背景参考与资格阈值是待真实语音校准的工程初值，不是已成熟的人声身份模型。
- 候选依据实际匹配谱峰及已解释峰抑制；身份证据不使用模型内共享峰，有限 partial 冲突明确进入 U。注册和观测采用绝对 Hz 谐波包络，参考与实时部分特征的方差适配仍是未校准近似，不承诺完全分离同 F0 隐藏声源。
- 新增固定 192 槽高阶谐波 partial 假设池，只补充未知/冲突解释，不据此出生声源、轨迹、别名或本人身份；注册和完整声源规则不变。没有删除高频负证据、放宽身份门槛或实施未经验证的方差膨胀。
- 短期反馈仅用于后续帧，注册锚点固定；无效数值/格式/设备/队列故障停止自身输出，不自动透传原声。程序能清理自己的 FIFO 与 WASAPI 流，不能保证立即清空第三方驱动或目标应用的内部缓存。
- WAV 与物理采集转换共用预分配抗混叠 FIR；线路输出另用有界异步 FIR 适配播放速率。单独声明转换群延迟，不把算法 CPU 时间当作完整新增延迟。
- 组件版本及“方法参考/独立实现/未采用”边界记录在 `components.lock.json`。本项目未直接复制列出的 GPL/AGPL 源码；分发前仍需按实际采用方式、编译依赖及模型/数据审核许可。

## 尚不能宣称的结果

合成信号契约测试只能验证因果、边界、数值、重建及固定状态，不证明真实多人语音效果。Q-01 至 Q-06、20 名隔离说话人盲测、清辅音/相似声/缺席泄漏、三小时游戏并行与 FPS、同一第三方线路配对 D_add、应用维护和实际线路/消费者组合均须另行完成并记录失败案例。改用现成线路仅简化音频接入，不会自动修复 MECAG 的重叠目标保留失败；不能暗换普通降噪或神经 TSE 冒称成功。

本仓库暂时只公开 README；需求、架构、原始方案及 `docs/` 文档保留本地，不随源码上传。构建产物、录音、加密档案及本机音频端点标识也不上传。旧自建驱动/transport 源码仅为历史研究，可选 legacy 测试默认关闭，不进入当前运行路径。
